# Python allocation snapshot — INCOMPLETE

A separate `tracemalloc` run covered the actual BTCUSDT January–March 2025 development archive replay, 2,160 bars, on the same ARM Linux Docker VM with a two-CPU quota and 4 GiB cap. It began tracing after the harness imports, used ten traceback frames, and took a snapshot after the replay had returned while its result was still retained. It does not count all allocations made before tracing, allocator-reserved memory, or native Rust/C allocations, and it does not measure transient allocation churn by source line.

The tracer reported a 52.5 MiB peak and 51.3 MiB still traced at the snapshot. The largest retained line entries were importlib loading at about 17.8 MiB, `economics/decisions.py:75` (`stance_record` mappings) at about 15.7 MiB in 120,960 blocks, and `experts/registry.py:663` (per-stance version strings) at about 4.1 MiB in 60,480 blocks. These are live Python allocator accounting, not independent peak-RSS contributions. The result retains decision/stance records; the findings suggest their storage merits investigation, but removing or reducing audit evidence would change semantics and is not proposed here. Exact lines and counts are in `allocations.json`.

The instrumented child took 89.91 s and reached 404.7 MiB RSS; the separate uninstrumented three-month median was 1.931 s. This approximately 46.6× timing ratio reflects very large tracing and snapshot overhead and run-to-run differences, not a production slowdown. The 90-second timeout narrowly did not expire, and cgroup memory events reported no OOM. RSS and traced bytes cannot be subtracted to identify native usage because they cover different populations and phases. No allocation profile was used for the benchmark timing verdict.

The harness now allows a configurable stack depth, defaulting to one to reduce overhead; reproduce the measured ten-frame setup using `reproduce.sh`. Full historical multi-asset memory scaling, native allocation attribution, streaming working-set behavior and target VPS acceptance remain unverified.

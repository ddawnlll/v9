# M2-02 — Typed `TraderDecision`, `IntentKind` and `ReasonCode` contracts

Objective: define the advisory decision schema for wave 1 (issue #17) so later waves import one
vocabulary instead of minting competing ones. Schema only; no execution semantics, no economic
claims.

## What was implemented

`src/v8_next/domain/decision.py` (new module, exports match WAVE_PLAN § Shared contracts):

- `DecisionAction` (WAIT/ENTER/HOLD/REDUCE/EXIT/ABSTAIN), `IntentKind`
  (NONE/MARKET_ENTRY/LIMIT_ENTRY/PROTECTIVE/REDUCE/EXIT/CANCEL), `VenueOrderStatus`
  (SUBMITTED/ACCEPTED/PARTIALLY_FILLED/FILLED/CANCELED/REJECTED/UNKNOWN), `ReasonCode`
  (24 stable string codes whose wire value equals the member name).
- `OpportunityLifecycle` (WATCHING/ARMED/ADMITTED/INVALIDATED/EXPIRED) plus a total,
  bidirectional mapping onto the repo's existing
  `v8_next.opportunities.models.OpportunityStatus` (`WATCHING↔CANDIDATE`,
  `ARMED↔CONFIRMED`, remaining three identical). `lifecycle_of` / `opportunity_status_of` are the
  only conversion points; a module import guard asserts the mapping is total over
  `OpportunityStatus`. `TERMINAL_LIFECYCLES` is derived data.
- `TraderDecision` — frozen, `extra="forbid"` pydantic v2 model with exactly the contract fields:
  `decision_id`, `decision_time_ns`, `instrument_id`, `opportunity_id`, `action`, `intent_kind`,
  `reason_codes`, `policy_version`, `belief_version_hash`, `advisory_only`.
- `derive_decision_id(...)` and `TraderDecision.create(...)`. The id is
  `canonical_digest("trader-decision-v1", [decision_time_ns, instrument_id, opportunity_id,
  action.value, policy_version])` — the repo's existing digest primitive from
  `v8_next.telemetry.identity`, so replay of identical inputs mints an identical id.

Enforced invariants (construction-time rejection):

1. `IntentKind.NONE` is legal only with `WAIT`/`ABSTAIN`.
2. Every non-`NONE` intent requires `ENTER`/`HOLD`/`REDUCE`/`EXIT`.
3. `advisory_only` is pinned `True` by a `Literal[True]` field plus a before-validator that rejects
   anything that is not exactly `True` (so `False`, `0`, `1`, `"true"`, `None` all fail).
4. `decision_id` must equal `derive_decision_id` for the record's own fields (tamper/replay check).
5. Reason codes must be unique and in canonical (sorted) order at construction;
   `TraderDecision.create` canonicalises instead.
6. Non-empty `instrument_id`/`policy_version`/`decision_id`; non-blank `belief_version_hash`.
7. Unknown venue states are rejected: `VenueOrderStatus("PENDING_NEW")` raises; `UNKNOWN` is the
   only "unreadable" member.

Separation of authorities, made structural rather than documentary: the model has no quantity,
price, side, order-type, client/venue order id or notional field, and `extra="forbid"` rejects
them; risk permission remains in `v8_next.risk.admission`; native order side effects remain in the
execution adapters. `advisory_only=True` is not an override flag.

## Residual risks / limits

- `ReasonCode` is a closed enum. Adding a code is additive; renaming or removing one changes the
  replay surface and must be treated as a policy-version break.
- `decision_id` does not include `reason_codes`, `belief_version_hash` or `intent_kind`, exactly as
  the contract specifies. Two records differing only in intent kind share an id, so a consumer that
  needs intent-level identity must key on `(decision_id, intent_kind)`.
- `TraderDecision` deliberately has no field for opportunity lifecycle, position presence or venue
  status; those are inputs to `M2-03` (`economics/legality.py`) and to later integration, which
  must not be smuggled back into this model.
- No economic, calibration or live-trading claim is made or implied; nothing here can place an
  order.
- BLOCKED items: none.

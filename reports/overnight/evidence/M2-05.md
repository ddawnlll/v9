# M2-05 — Immutable decision receipts and explainable policy provenance

Objective: make every advisory decision auditable after the fact (issue #20) with an append-only
snapshot binding the decision to the exact inputs it used, the belief version, the opportunity
episode, the policy hash and the constraints that shaped it — without ever implying an executed
trade or cashflow.

## What was implemented

`src/v8_next/telemetry/decisions.py` (new module):

- `DecisionInputRef` — one input event (`observation_id`, `available_at_ns >= 0`).
- `ReceiptInputs` — caller evidence bundle (`inputs`, `constraints`); `.ordered()` sorts by
  observation id and rejects duplicate references.
- `DecisionReceipt` (frozen, `extra="forbid"`) — records `decision_id`, decision time, instrument,
  opportunity id, action, `proposed_intent`, structured `reason_codes`, `policy_version`,
  `policy_hash`, `belief_version_hash`, `observation_ids`, `input_available_at_ns`,
  `max_input_available_at_ns`, `constraints`, `advisory_only=True` and a content `digest`.
  There is no quantity, price, fill, cashflow, venue-order or execution field.
- `DecisionReceipt.create(decision, inputs)` — mints the digest. It refuses an unknown policy
  version (`UnknownPolicyVersion`) because an uncertifiable hash is not provenance; it does *not*
  enforce PIT itself, so tests can craft the self-consistent non-PIT value a verifier must reject.
- `DecisionReceipt.verify(expected_policy_hash=None) -> bool` — recomputes the digest and checks
  schema, policy hash against `v8_next.economics.policy.POLICY_HASHES`, action/intent agreement,
  per-input availability (all `<= decision cut`), `max_input_available_at_ns` == max of the inputs,
  sorted/unique observation ids and reason codes, canonical constraints, and the
  `derive_decision_id` binding. Any failure returns `False`; nothing raises.
- `DecisionLedger` — append-only in-memory store. `append(decision, inputs, *, allow_orphans=False)`
  rejects non-PIT input (`ReceiptRejected`, code `NON_PIT_INPUT`), any receipt failing `verify`,
  unknown policy versions and orphan decisions (`OrphanDecision`); re-appending the same
  `decision_id` with an identical body is idempotent (returns the original record, one entry),
  while a differing body under the same id raises `ReceiptConflict`. `verify(receipt)` delegates to
  `receipt.verify()`. `orphans()` returns sorted ids of actionable (`not WAIT/ABSTAIN`) decisions
  with no referenced opportunity; `allow_orphans=True` exists only for auditing pre-existing dirty
  upstream data. `receipts()` returns an immutable snapshot in append order.
- Digest payload: fixed field order over content only (no wall clock, no insertion position, no
  ledger size), domain-separated with the `decision-receipt-v1` tag via
  `v8_next.telemetry.identity.canonical_digest`.

## Tests

`tests/test_decision_receipts.py` — 31 tests, all passing:

- Provenance: every field is copied from the decision; policy hash equals `POLICY_HASH`; optional
  belief hash recorded as `None` when absent; no execution fields in the schema; model frozen;
  unknown fields rejected.
- Determinism: identical replay yields identical digest/receipt; two independent ledgers mint the
  same digest; input order does not change the digest; constraints and reason codes do change it.
- PIT: a future-dated input makes `verify()` false and `append` raise `ReceiptRejected` with code
  `NON_PIT_INPUT` while leaving the ledger empty; an input available exactly at the cut is accepted.
- Append-only: duplicate append is idempotent (same object, `len == 1`); conflicting duplicate
  raises `ReceiptConflict` and preserves the original digest; snapshots do not mutate.
- Orphans: default append of an actionable decision without an opportunity raises
  `OrphanDecision`; `allow_orphans=True` records it and `orphans()` reports it; `WAIT` without an
  opportunity is legal and not an orphan; a clean ledger reports none.
- Verification: tampered constraints, tampered policy hash, tampered `decision_id` and
  `expected_policy_hash` mismatch all return `False`; duplicate observation references are refused.
- Integration: constraints and reason codes taken from `TraderDecisionPolicy.explain()` are
  receipted, `policy_hash` matches the explanation, and the replay digest is identical.
- No execution path: AST scan shows no `nautilus`/`adapter` import and no order verb call.

## Residual risks / limits

- The ledger is in-memory and single-writer; durable storage and concurrency control are storage
  concerns outside this issue (documented in the class docstring, not silently assumed).
- PIT proof at receipt level covers the declared observation references. Policy-level `as_of_ns`
  is enforced only when the injected belief/opportunity view exposes it; a caller that omits it
  makes no claim, which the M2-04 report records explicitly.
- Certifying `policy_hash` couples receipts to `v8_next.economics.policy.POLICY_HASHES`: an older
  policy version not present in the registry is refused rather than archived unverified. Replaying
  historical receipts after a policy removal would require restoring the version in that registry.
- `orphans()` is an audit surface, not an enforcement gap: the default append path cannot create an
  orphan. `allow_orphans=True` is the only way to record one and is intended for imported history.
- Receipts record the *proposed* intent only; no fill, cashflow or P&L claim is made and no
  execution adapter is imported. BLOCKED items: none.

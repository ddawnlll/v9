## Objective

Deliver **one** product-level vertical slice, not another engine: PIT observations →
`MarketBeliefV1` → the 28 canonical experts → `OpportunityBook` → `TraderDecision` →
entry / position / portfolio proposals → hard-risk observation → shadow receipts. The
V8 native replay stays the validated control arm; every novel adaptive decision is
routed to shadow only, and the product is not collapsed into an entry veto.

## What was implemented

New module `src/v8_next/app/shadow_trader.py` — a thin orchestrator. It re-implements
none of the delivered layers and owns no state beyond declared policy constants.

**Typed event script.** `MarketEvent` is the closed base of `PositionUpdate`,
`VenueUpdate`, `ProtectionUpdate`, `RiskUpdate`, `OpportunityUpdate`, `BarUpdate`,
`QuoteUpdate`, `FundingUpdate`, `CutUpdate`. Each event carries a fact time and an
`available_at_ns`; `available_at < event_time` is refused at construction.

**Declared order.** `_canonical_events` sorts a caller's sequence by
`(event_time_ns, kind rank, instrument, payload digest)`. The order is part of the
contract, so *reordering independent events yields an equal trace*, and an ambiguous
duplicate (`AMBIGUOUS_EVENT_ORDER`) fails closed instead of being resolved by input
position.

**Per cut, in order:** `build_view` (PIT partition) → `assemble_context` (M15) →
`advance(belief)` → `produce_evidence` (28 witnesses, context-bound) →
`OpportunityBook.snapshot` + `recurrent.advance` (one evaluation per episode per
instant) → `TraderDecisionPolicy.evaluate` + `explain` → ENTER ⇒ `build_intent` +
`evaluate_entry`; HOLD/REDUCE/EXIT ⇒ `evaluate_position` + `evaluate_management` with
the decision action as a *competing candidate* (escalation only) → portfolio
`allocate_challenger` over the cut's simultaneous entry candidates → `DecisionLedger.append`
receipt + `OpportunityBook.link_decision`.

**`ShadowTrace` (frozen pydantic).** Ordered `steps` (cut time, belief version hash /
status / quality, evidence coverage + abstain count, opportunity id + status +
decision lifecycle, position presence, venue, risk status/reason, decision id + action
+ intent + canonical reason codes, entry intent id/mode/reason, management id +
advisory action + proposal ids, allocation outcome + id, receipt digest, and every
input's availability clock), `receipt_ids`, `native_side_effects` (structurally empty,
pinned `NO_NATIVE_SIDE_EFFECTS`, model refuses a non-empty value) and a `parity` block.
`to_json()` is canonical JSON (`sort_keys`, no whitespace).

**Zero native side effects, proven structurally.** Compiled into the model, not a
convention: (a) `native_side_effects` is a typed empty tuple with a rejecting
validator; (b) the module imports no execution/broker/exchange/venue-client surface and
binds no order verb (AST-pinned test); (c) the parity block carries the six native
digests captured **before** and **after** the whole run via
`capture_replay(control, policy_state="OFF")` and requires them equal. That equality is
a determinism check of the policy-off control replay, not engine parity: the slice has
no execution surface to compare, so the block reports
`verification="NO_EXECUTION_SURFACE"` together with the structurally empty
`native_side_effects` and pins `engine_parity="NOT_RUN"`. (An earlier revision copied
the control capture into a "shadow" signature and ran `assert_shadow_unmutated`
against it; that comparison could never fail and is withdrawn.)

**Engine-level parity is NOT_RUN.** No shadow engine and no native execution surface
are wired here, so no shadow-vs-native parity claim is made anywhere. The `NativeSession`
protocol in `evaluation/shadow_parity.py` is the contract a future engine-level parity
check must inject; this slice does not implement or consume it.

**Hard risk is read-only.** `RiskObservation` is an input (`advisory_only=True`). It
names its snapshot time; a reading older than `RISK_MAX_AGE_NS` (2 h) is *unknown*, not
extended. `AVAILABLE | DENIED | UNKNOWN` maps to the policy's capacity state; a
non-`AVAILABLE` reading blocks the portfolio plane outright (`NOT_ATTEMPTED`), and an
omitted constraint still fails closed inside `allocate_challenger`. Every emitted
proposal keeps `advisory_only` pinned; protective proposals keep
`requires_risk_permission=True` and the trace reports it per step.

**Evidence discipline.** `produce_evidence` requires the belief to name the cut's
decision clock; the slice keeps a guard (belief stamped elsewhere, or a cut with no
closed bar) that records `evidence_coverage = 0` and lets the policy fail closed rather
than crashing mid-trace. Witness weight is the determinacy the row already carries
(`1` asserted / `0` abstained): an abstaining witness is counted in coverage and cannot
vote. No weight is fitted.

## Residual risks / limits

- **Synthetic tape.** The slice is validated on a scripted, declared event tape. No
  altcoin tape, no 24–48 h soak, no sealed OOS was used, so nothing here is evidence of
  economic edge. Stated, not implied.
- **Evidence weights.** A witness contributes its own determinacy (0/1), so the panel
  arithmetic is a vote of asserted witnesses, not a calibrated weight. Any fitted
  weighting is a different ticket with its own validation.
- **Allocation sizing.** The portfolio plane requests a declared `ALLOCATION_FRACTION`
  (10 %) of equity per candidate; that is a shadow policy constant, not a sizing model.
  Admitted size is advisory and is never submitted.
- **Venue grid provenance.** Each candidate's lot grid comes from its own instrument's
  fresh risk reading; an incomplete grid refuses the whole batch (`NOT_ATTEMPTED`)
  instead of allocating siblings on a guessed grid. A real heterogeneous-venue batch
  therefore needs one complete reading per instrument, which the risk plane must supply.
- **Risk-plane contract.** `RiskObservation` is a reading; this slice cannot prove the
  native authority agrees with it. If the risk plane publishes an `AVAILABLE` reading it
  later contradicts, the trace records what was read at the cut — the native authority
  remains the only one that can act.
- **Committed-exposure attribution.** `committed_exposure` is an account total. It is
  charged to an instrument/sector only when the reading also supplies the exact split
  (`HardRiskLimits.instrument_committed` / `sector_committed`). Without it the
  challenger returns `BLOCKED_EXPOSURE` / `UNKNOWN_EXPOSURE_DETAIL`; the slice never
  invents an attribution (the previous code charged the whole total to every candidate,
  which double-counted it and vetoed every instrument).
- **Engine parity.** NOT_RUN. `verification="NO_EXECUTION_SURFACE"` and
  `engine_parity="NOT_RUN"` are the only claims the trace makes; the policy-off digest
  equality around the run is a determinism check of the control replay.
- **Protection at exit.** When a stop is already through the market, no protective
  proposal is emitted (placing it would trigger immediately). The EXIT step therefore
  carries an advisory with zero proposals; that is a documented consequence of
  `evaluate_management`, not a missing link.
- **`on_candle` transitions.** The book's own price/TTL invalidation scan is wired and
  runs on every closed bar; on this tape the explicit reassessment lands first, so the
  scan is exercised without transitioning. The transition path itself is covered by the
  book's own suite.
- **One ledger, one book.** `DecisionLedger` and `OpportunityBook` are the delivered
  in-memory ones; durability is a storage concern and no second OMS was introduced.

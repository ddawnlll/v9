## Objective

Introduce a versioned observation view that distinguishes event time, exchange
publication, local receipt, availability and the decision cut; construct
observations only from data known by the cut; preserve provenance; expose typed
data-quality states; reject amended future values and contradictory duplicates.

## Implemented (`src/v8_next/domain/observation.py`)

- `QualityState` (`OK | STALE | MISSING | CONTRADICTORY | AMENDED_FUTURE | UNKNOWN`)
  and `ObservationKind` (`BAR | FUNDING | OPEN_INTEREST | MARK | QUOTE | LIQUIDATION`).
- `Observation` — frozen Pydantic v2 model with the contract fields plus causal
  validation: exact-integer clocks (bool/float/str rejected), non-empty
  instrument/source, `received_at >= event_time`,
  `available_at >= received_at`, `event_time <= published_at <= available_at`,
  non-negative sequence.
- `ObservationRejection` + `RejectionReason` (`NOT_YET_AVAILABLE`,
  `QUALITY_BLOCKED`) — typed evidence for records kept but unusable.
- `observation_id(observation)` — SHA-256 content id over instrument, kind,
  event/availability clocks, source, sequence, quality and canonical-JSON
  payload (provenance included; identical content → identical id).
- `PitViolationError(ValueError)` with a machine-readable `code`
  (`CONTRADICTORY`, `AMENDED_FUTURE`, `NOT_YET_AVAILABLE`, `QUALITY_BLOCKED`,
  `MALFORMED_BAR`, `MALFORMED_PAYLOAD`).
- `build_view(observations, *, cut_time_ns) -> ObservationView`:
  - deep-copies the snapshot first, so later mutation/cloning of caller records
    or payload dicts cannot rewrite an earlier view;
  - raises `AMENDED_FUTURE` for any amended-future record;
  - partitions `available_at > cut` into `ObservationRejection(NOT_YET_AVAILABLE)`;
  - raises `CONTRADICTORY` when two usable records share
    `(instrument_id, kind, event_time)` with differing payloads; identical
    payload duplicates are deduped deterministically;
  - precomputes immutable indexes (mapping-proxy backed) for bars, quality,
    quality atoms and ids.
- `ObservationView` — frozen dataclass:
  - `cut_time_ns`, `max_input_available_at`;
  - `bars(instrument_id)` returns only `OK`/`STALE` BAR payloads materialised as
    `v8_next.domain.market.Candle` (malformed candles fail closed; `MISSING`
    never fabricates a bar);
  - `quality(instrument_id)` / `quality_at(instrument_id, at_ns)` return the worst
    quality, with `MISSING` when nothing is known; `quality_at` clamps to the cut
    so later judgements cannot leak backwards;
  - `observation_ids()`, `observations()`, `rejections()`;
  - `require_observation(id)` and `require_bar(instrument_id, start_ns=...)`
    raise `PitViolationError` when the record exists but is unusable instead of
    returning silent absence.
- `worst_quality` / `quality_severity` — deterministic fail-closed ordering
  `OK < UNKNOWN < STALE < MISSING < CONTRADICTORY < AMENDED_FUTURE`.

## Acceptance evidence

- **Future records cannot rewrite earlier views** — input payload dict and source
  list are mutated after `build_view`; bars and `observations()` still show the
  original values (`test_view_is_immutable_and_survives_input_mutation`).
- **`max_input_available_at` exposed** — asserted as `M15` on a view whose latest
  usable record is available at `M15`; empty-view bound is the cut
  (`test_usable_and_rejected_partitions_are_explicit`,
  `test_empty_view_reports_missing_everything`).
- **Late publication is typed, not silent** — `rejections()` carries
  `NOT_YET_AVAILABLE`; `require_observation`/`require_bar` raise with that code.
- **Contradictory duplicates fail closed** — differing payloads at the same
  instrument/kind/event time raise `CONTRADICTORY`
  (`test_contradictory_duplicates_raise`); a contradictory *future* duplicate does
  not poison the earlier view (`test_contradictory_future_duplicate_does_not_poison_the_earlier_view`).
- **Amended future raises** — `test_amended_future_observation_raises_even_when_requested_late`.
- **MISSING/STALE surfaced** — MISSING bars are never fabricated into candles but
  remain in the observation set and degrade quality; STALE bars stay queryable
  (`test_missing_and_stale_are_surfaced_not_dropped_or_fabricated`,
  `test_stale_bars_remain_queryable_with_stale_quality`).
- **Lineage validation** — availability before receipt, receipt before event and
  publication after availability all raise `ValidationError`
  (`test_observation_lineage_causality_is_enforced`); bool clocks rejected.
- **Determinism** — content ids/bars are independent of input order
  (`test_observation_identity_is_content_addressed_and_order_independent`).

## Residual risks

- `available_at >= received_at` is enforced at the schema boundary. A real feed
  with clock skew must normalise before constructing `Observation`; the model
  fails closed rather than accepting a record that claims availability before
  receipt.
- BAR semantics are pinned: `event_time` must equal payload `start_ns`, and the
  payload must be canonical JSON (Decimal is normalised to string; sets and other
  non-JSON values raise `MALFORMED_PAYLOAD`).
- Only `OK`/`STALE` bars become `Candle`s. `CONTRADICTORY`/`UNKNOWN`/`MISSING`
  BAR payloads remain visible through `observations()`/`quality()` but are blocked
  from `bars()`/`require_bar()` (code `QUALITY_BLOCKED`).
- `max_input_available_at` is the cut for an empty view (a safe upper bound with
  no consumed input); consumers should read `observation_ids()` to distinguish
  "nothing consumed".
- Pydantic frozen models do not freeze nested `payload` dicts. `build_view`
  snapshots them, and no view index depends on post-build payload mutation, but a
  caller that mutates a payload returned by `observations()` is mutating its own
  copy of the record, not a view index.

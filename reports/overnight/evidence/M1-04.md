## Objective

Update the market belief only when its dependencies change, keep regime changes
auditable and hysteretic, make stale data and missing inputs explicit
(`STALE`/`ABSTAIN`/`UNKNOWN`, never a silent default), keep re-application
idempotent, and bind threshold changes to an explicit policy version.

## Implemented (`src/v8_next/belief/update.py`)

- `BeliefPolicy` (frozen): `version`, `window_bars=20`, `min_bars=6`,
  `regime_min_score=0.35`, `hysteresis_band=0.10`, `min_candidate_streak=2`,
  `staleness_horizon_ns=2h`, `shock_multiple=3`, volatility thresholds,
  `structure_band_bps=5`, `swing_band=0.25`, `uncertainty_margin_low=0.15`,
  `uncertainty_margin_high=0.05`. `BELIEF_POLICY_VERSION = "belief-policy/1"`.
  The validator recomputes the default threshold map and **refuses any deviation
  under the default version** (`BeliefPolicyError`, deliberately not a
  `ValueError` so pydantic cannot erase the code). `policy_digest()` is stored in
  `provenance.policy_digest`.
- `update_trigger(previous, view, context, *, now_ns, policy=None) -> UpdateTrigger | None`:
  cheap dependency assessment with no feature arithmetic.
  `INITIAL | INPUT_CHANGED | STALENESS_CROSSED | POLICY_CHANGED | None`.
- `advance(previous, view, context, *, now_ns, policy=None) -> MarketBeliefV1`:
  - **incremental**: a dependency fingerprint over the *consumed* inputs
    (`observation_ids` of window bars + latest mark/quote/OI/funding,
    `decision_time_ns`, quality at decision, the three alignment states, policy
    digest) is compared first. Equal fingerprint and equal policy version →
    return the previous belief object unchanged; no feature arithmetic runs.
    An observation of a kind the belief does not consume (e.g. `LIQUIDATION`)
    changes nothing.
  - **idempotent**: re-applying the same snapshot at the same `now_ns` returns
    the identical belief and therefore the identical `version_hash` and the
    identical transition `event_id`; a second transition event is never minted.
  - **stale**: `now_ns > max_input_available_at + staleness_horizon_ns` produces
    `status=STALE`, `quality` degraded to `STALE`, `uncertainty=HIGH`,
    `transition=None`, `is_actionable_evidence()=False`. A stale belief is never
    promoted back to `FRESH` without a changed dependency set; new evidence
    restores `FRESH`.
  - **fail closed on ordering**: `now_ns` earlier than the inputs (or than the
    previous belief's inputs) raises `BeliefContractError` with code
    `NOW_BEFORE_INPUT`; a belief/context instrument mismatch raises
    `INSTRUMENT_MISMATCH`; a previous belief whose hash does not re-derive raises
    `BeliefIntegrityError`.
  - **abstains**: fewer than `min_bars` admissible bars or no complete horizon →
    `status=ABSTAIN`, `origin=MISSING_INPUT`, `missing_inputs=("bars","horizon")`
    as applicable, regime `UNKNOWN`, regime scores `unknown=1`, dimensions
    `UNKNOWN`, empty input id set.
  - **hysteresis**: a challenger must beat the incumbent's score *in the current
    score set* by `hysteresis_band` **and** persist `min_candidate_streak`
    consecutive evidence sets before it is adopted. Suppressed challengers stay
    observable (`regime_candidate`, `candidate_streak`); accepted ones mint one
    `TransitionEvidence` (from/to regime, reason, band, both scores, trigger
    observation ids, occurrence time, previous state id). Aged evidence never
    changes the label (`STALE` keeps the incumbent), so no unaudited transition
    can hide inside a stale belief.
  - `changed_fields` is computed per dimension so an audit can see exactly which
    parts of the view moved (`policy_version` included).

### Reuse of `v8_next.telemetry.belief`

That module is the ex-ante **receipt ledger** (stages, append-only receipts,
identity). It contains no market-state arithmetic, so nothing there applies to
the belief computation itself. What is reused is the digest primitive
(`telemetry.identity.canonical_digest`) and the module's invariant 1, which
`tests/test_market_belief.py::test_belief_carries_no_unavailable_ex_ante_dimensions`
enforces against this schema's field set (`UNAVAILABLE_EX_ANTE_DIMENSIONS` may not
appear as belief fields or be accepted as input).

## False-transition fixture (documented behaviour)

`BORDERLINE` is 19 deltas (`12 × +1.5, 1 × +1.0, 6 × -1.0`) giving path
efficiency exactly `0.52`, hence `trend=0.520000`, `range=0.480000` — a 0.04
margin inside the 0.10 band. Sequence in
`test_hysteresis_prevents_flip_flopping_on_a_borderline_sequence`:

| cut | window | candidate | incumbent score | decision |
|---|---|---|---|---|
| 19 | RANGE (efficiency 0.05) | RANGE | — | regime = RANGE |
| 38 | BORDERLINE | TREND (0.52) | RANGE 0.48 | hold: 0.52 < 0.48 + 0.10 |
| 57 | RANGE | RANGE | — | streak reset to 0 |
| 76 | BORDERLINE | TREND (0.52) | RANGE 0.48 | hold again |
| 95 | RANGE | RANGE | — | no transition ever |

Uncertainty at cut 38 is `HIGH` (top-two margin 0.04 < 0.05). The same sequence
under `BeliefPolicy(version="belief-policy/1-narrow-band", hysteresis_band=0.01)`
flips to `TREND` at cut 57 — i.e. the band, not the streak, is what prevents the
flip-flop, and a different threshold set carries a different policy version.

## Acceptance evidence

- **Stale belief never fresh** — `test_stale_belief_is_never_fresh`: fresh at
  `cut + horizon`, `STALENESS_CROSSED` one nanosecond later, `STALE` after that,
  unchanged hash on repeat, `STALE` cannot be re-read backwards
  (`NOW_BEFORE_INPUT` on rewind), and new evidence restores `FRESH`.
- **Updates idempotent** — `test_identical_evidence_is_idempotent`: second
  `advance` returns the same object, same hash, `update_trigger(...) is None`.
- **One transition event per applied observation** —
  `test_reapplying_evidence_mints_one_transition_event`: the switched belief has
  exactly one `TransitionEvidence` (previous state id = previous hash, band 0.10,
  trigger ids from the new snapshot); re-applying that snapshot reproduces the
  same `event_id`; the confirming snapshot adds none; exactly one distinct event
  id exists across the whole sequence.
- **Hysteresis / false transitions** — the section above plus
  `test_policy_thresholds_are_pinned_and_versioned` (exact threshold pinning).
- **UNKNOWN/ABSTAIN observable** — `test_missing_inputs_during_an_update_are_observable`
  (`ABSTAIN`, `origin=MISSING_INPUT`, `missing_inputs`, `regime_label=UNKNOWN`,
  `changed_fields`); `UNKNOWN` status covered in `test_market_belief.py`.
- **No recompute for irrelevant observations** —
  `test_irrelevant_observation_does_not_recompute_the_belief`: a new
  `LIQUIDATION` observation extends `view.observation_ids()` but
  `update_trigger` is `None` and `advance` returns the previous belief object
  with unchanged input ids.
- **Threshold changes carry a version** —
  `test_policy_thresholds_are_pinned_and_versioned` (deviation under the default
  version refused) and `test_policy_change_is_an_explicit_rebuild`
  (`POLICY_CHANGED`, new `policy_version`, new `policy_digest`, no transition
  reused across policies).
- **PIT guards** — `test_update_guards_fail_closed` (`NOW_BEFORE_INPUT`,
  `INSTRUMENT_MISMATCH`, `BeliefIntegrityError` for a tampered previous belief).

## Residual risks

- Hysteresis compares the challenger against the incumbent's score **under the
  current window's scores**, not against the score that originally elected it.
  This is deterministic and documented, but a later audit may prefer an
  election-time score snapshot.
- `min_candidate_streak` counts evidence sets, not elapsed time; a burst of
  snapshots inside one bar can therefore confirm a challenger faster than a
  wall-clock rule would. Bars only change the fingerprint when a new bar closes,
  so in practice a streak is one bar apart.
- A regime that is `UNKNOWN` because required inputs were missing requires
  `min_candidate_streak` evidence sets to recover, by design (no fast path out of
  abstention).
- Policy version comparison is by `version` string; the threshold digest is
  recorded but not used to reject a *mislabelled* custom policy (only the default
  version is strictly checked).

# M4-01 — Preregister economic hypotheses, matched baselines and acceptance gates (#29)

Status: **IMPLEMENTED_WITH_EVIDENCE** (integration and issue closure remain the director's call).

## Objective

Lock the hypothesis, the matched controls, the cost terms and every acceptance gate into a
machine-readable record *before* any sealed data is read, so a post-hoc loosening cannot be
presented as a preregistered result. The record must be complete enough that a result can be
diffed against it field by field.

## What was implemented

`src/v8_next/evaluation/preregistration.py` (new, 545 lines)

- `Preregistration` — frozen pydantic model carrying `hypothesis_id`, `statement`,
  `intervention`, `control_arms`, `unit_of_comparison`, `dataset_role`, `costs`,
  `minimum_trades`, `max_drawdown`, `primary_metrics`, `secondary_metrics`,
  `expected_direction`, `accepted_outcomes`, `decision_rule`, `hypothesis_budget`,
  `created_ns`, `code_sha`, `config_sha`, `version` (`PREREGISTRATION_VERSION = "1.0"`).
- `Arm`/`ArmKind` — `V8_BASELINE`, `RANDOM_ENTRY_MATCHED_EXITS`, `SIMPLE_CONTROL_POLICY`,
  `V9_INTERVENTION`. Every arm carries `MatchedDimensions(calendar, capital, venue,
  opportunity_exposure, exit_policy)`; validation requires a V8 baseline **and** a
  random-entry-with-matched-exits arm, and every control arm must equal the intervention's
  matched dimensions exactly (same calendar/capital/venue/exposure/exit policy).
- `CostModel` — `fee_bps_per_side`, `funding_bps_per_day`, `slippage_bps_per_side`,
  `funding_included`, `venue`. Absent (`None`) and negative terms are refused; an explicit
  `0` is a declared value and is accepted. `funding_included=False` is refused: a comparison
  that drops funding is missing a cost term by construction.
- `HypothesisBudget` — `family`, `max_hypotheses`, `max_trials`, `alpha`, `correction`
  (`BONFERRONI|HOLM`, shared vocabulary from `protocol.py`).
- `digest()` — `canonical_digest("v8-next-preregistration", model_dump(mode="json"))`
  (`v8_next.telemetry.identity`), so identical content reproduces the identical identity and
  `to_json`/`from_json` preserve it. Decimals are serialised as strings by pydantic's JSON
  mode; money is never a float.
- `validate()` — collects **every** problem and raises one `PreregistrationError`
  (`code="PREREGISTRATION_INVALID"`) with `field` (first) and `fields` (all). It refuses:
  a missing control arm, a missing random-entry arm, an unmatched control arm, a missing cost
  term (each of fee/funding/slippage), dropped funding, a missing negative-outcome rule
  (`NO_EDGE` and `STOP` are both mandatory), a blank decision rule, a missing budget and each
  incomplete budget component, a missing drawdown or minimum-trade gate, a missing dataset
  role/unit/metric/direction/timestamp/code SHA/config SHA, an unsupported version, and
  `PASS` preregistered as an accepted outcome (PASS is claimed by evidence, never registered).
- `gates() -> AppliedGates` — the registered gate vector: role, unit, primary metric,
  minimum trades, max drawdown, alpha, max hypotheses, correction, all three cost terms and
  the accepted outcomes.
- `compare_against_result(result)` — re-derives `gates()` and diffs it against
  `ExperimentResult.gates` plus `preregistration_digest` and `hypothesis_id`. Any difference
  raises `PostHocGateChange` (`code="POST_HOC_GATE_CHANGE"`) whose `fields` names every
  changed field and whose message names them too. A clean comparison returns
  `ComparisonReceipt(checked_fields=...)`.

## Acceptance evidence

`tests/test_preregistration.py` — 38 passed.

- Round trip: `Preregistration.from_json(p.to_json()).digest() == p.digest()`.
- Digest determinism: identical fields give identical digests; changing
  `max_drawdown`, `dataset_role` or `statement` changes the digest.
- Validation refusals, one test per element: control arm (empty tuple), missing
  random-entry arm, unmatched control capital, `costs=None`, fee term, funding term,
  slippage term, dropped funding, empty/partial negative-outcome tuple, blank decision rule,
  `hypothesis_budget=None`, and each incomplete budget component (hypotheses, alpha,
  correction), plus drawdown/trades gates; one aggregate test asserts all four headline
  elements are reported in one raise.
- Post-hoc gate change: parametrised over `max_drawdown`, `minimum_trades`, each cost term,
  `alpha`, `max_hypotheses`, `dataset_role`, `unit_of_comparison`, `primary_metric` and
  `accepted_outcomes` — each raises `PostHocGateChange` naming that field. A swapped digest
  and a renamed hypothesis are each detected.
- Controls share calendar/capital/venue/opportunity exposure/exit policy (matched-dimension
  equality test above).

## Residual risks / NOT_RUN

- No economic claim and no live-trading path: the module constructs no order object and
  imports no execution adapter.
- `validate()` is an instance gate, not a constructor validator (deliberately, so the refusal
  names the missing element). A caller that never calls `validate()` holds an incomplete
  record; `assess_verdict` in `protocol.py` always calls it before any PASS.
- Preregistration persistence (SQLite registration table) is **NOT_RUN**: the digest is the
  identity and the record serialises, but no store wiring was added in this slice.
- Wiring into `evaluation.runner` / `gate_resolution` is **NOT_RUN** (out of slice scope).

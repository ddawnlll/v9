## 1. What was implemented

`src/v8_next/evaluation/verdict.py` separates the five promotion questions instead of collapsing
them into one score:

- `PromotionDimension` — `MECHANICAL | PIT | ECONOMIC | RESOURCE | LIVE_APPROVAL`.
- `DimensionStatus` — `PASS | NO_EDGE | INCONCLUSIVE | FAIL | NOT_RUN | BLOCKED`.
- `EvidenceRef` — repository-relative path bound to the SHA-256 it had when read;
  `matches(root)` re-hashes the file.
- `DimensionVerdict` — frozen `(dimension, status, evidence, notes)`.
- `PromotionMatrix` — the five verdicts with a model validator that refuses a slot carrying the
  wrong dimension and refuses any `LIVE_APPROVAL` status other than `BLOCKED`.
  - `overall_verdict` = worst of all five under
    `BLOCKED > NOT_RUN > FAIL > INCONCLUSIVE > NO_EDGE > PASS`.
  - `scientific_verdict` = worst of the four measurable dimensions (live approval excluded,
    because it is never granted here).
  - `live_approved` is a **property that returns the literal `False`**; there is no model field
    and no assignment path that can set it `True`. `requires_owner_authorization` returns `True`.
  - `verify(root)` re-hashes every evidence ref and turns a dimension `BLOCKED` when a file is
    missing or its digest changed.
- `build_matrix(*, mechanical, pit, economic, resource, live_approval)` — assembly plus the
  live-approval refusal.
- `render_markdown(matrix)` — deterministic published document: every dimension, verdict,
  evidence path + full SHA-256, blocked prerequisites, failed/inconclusive dimensions, the exact
  next step and the promotion policy. No clock, no network.
- `collect_from_artifacts(root)` — reads the repository's real evidence:
  - mechanical: `reports/provenance/baseline.json` (`code_sha`, `baseline_tests.passed`) +
    M0-02/M0-03 lineage evidence. When `reports/overnight/test-results.jsonl` is present every
    row is **inspected**, not just hashed: a row with non-zero `failed`/`errors` or a
    `result`/`status` beginning with fail/error blocks the dimension with a named reason and the
    log ref. A corrupt log still blocks.
  - PIT: M1-01…M1-04 evidence + at least one dataset `AVAILABLE` in the provenance baseline;
  - economic: requires all three of `reports/evaluation/preregistration.json`,
    `reports/evaluation/access_report.json`, `reports/evaluation/costed_result.json`; absence is
    `NOT_RUN`, forged/mismatched content is `BLOCKED`; the costed result must bind the
    preregistration file digest, the registered dataset role, the registered fee/funding/slippage
    terms and report a numeric net return;
  - resource: only receipts that declare both a deployment `scope` and `within_rss_target`
    qualify; throughput-only receipts are reported as auxiliary, not as qualification;
  - live: always `BLOCKED`.
- CLI: `python -m v8_next.evaluation.verdict --root . --out reports/overnight/V9_VERDICT.md`.

### 1.1 ECONOMIC `PASS` is earned, never declared (repair of the self-declared-string defect)

Before this repair the ECONOMIC dimension status was copied verbatim from
`costed_result.json`'s `verdict` string, so a registration with
`accepted_outcomes=[NO_EDGE, INCONCLUSIVE, STOP, INVALID]`, `minimum_trades=30` and a costed
`net_return=-0.50`, `trades=1`, `verdict=PASS` rendered `ECONOMIC PASS`. A `PASS` claim is now
refused (dimension `BLOCKED`, one named reason per failed predicate) unless all of:

1. the costed `net_return` is strictly positive;
2. `trades` is an integer at or above the registered `minimum_trades`;
3. the registration does **not** pre-accept `PASS` — the repository's own
   `Preregistration.validate` refuses `PASS` in `accepted_outcomes` ("PASS is claimed by
   evidence, never preregistered as accepted"), so a registration that pre-accepts its own
   conclusion is itself inadmissible;
4. the registered decision rule is satisfied concretely: the costed `uncertainty` block must
   declare the registered `HOLM` correction, the registered family size
   (`hypothesis_budget.max_hypotheses`), a numeric interval `[ci_lower, ci_upper]` that excludes
   zero and contains `net_return`, and either `p_value` or the interval's `alpha` at or below
   the Holm-adjusted `alpha / family_size`.

Non-`PASS` outcomes (`NO_EDGE`, `INCONCLUSIVE`, `STOP`, `INVALID`) pass through **only** when
they are listed in the registered `accepted_outcomes`; otherwise the dimension is `BLOCKED`.
A costed result whose `preregistration_digest` differs from the SHA-256 of
`reports/evaluation/preregistration.json` on disk is refused.

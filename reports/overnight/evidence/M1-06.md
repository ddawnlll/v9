# M1-06 (#15) — shared incremental indicators and feature cache across all experts

**Status: implementation COMPLETE, measurement COMPLETE for the measured scope — director certifies.**
The 28 expert stances and reason codes are identical with and without the cache over the real
authorised tape (2,160 bars, 60,480 stances, one decision digest). The shared feature reads are
5.73× faster with identical values. 40-leg/12-month scope is **NOT_RUN**.

## 1. Objective

A bounded shared PIT feature state that all 28 experts can read without changing any verdict:
versioned, invalidated when inputs change, bounded in memory, and equal to the old engine in
policy-off mode (stances + reason codes), with runtime / RSS / invalidation parity recorded.

## 2. Implementation — `src/v8_next/experts/cache.py` (new, 509 lines)

### 2.1 Keying

`CacheKey = (version, instrument_id, spec_key, as_of_ns, input_digest)`.

* `FEATURE_CACHE_VERSION = "v9.feature-cache.1"` is part of every key, so a kernel/warmup change
  makes old entries unreachable instead of silently reinterpreted.
* `spec_key` is a `FeatureSpec` (`name` + integer `params`) validated once at construction; the
  module ships `RSI_14`, `TREND_EMAS`, `SIGNIFICANT_SWINGS_10`, `MACD_LINE`, `MEAN_RANGE_14` as
  constants so no pydantic object is built per bar.
* `as_of_ns` is the frame's decision timestamp: values for different availability cuts never share
  an entry.
* `input_digest` is a chained SHA-256 over the *exact* prefix bytes (columns `start_ns`, `end_ns`,
  `open`, `high`, `low`, `close`, `volume`, in that order), so a cached value can never be served
  for different inputs.

### 2.2 Incremental extension

`_sync(frame)` keeps one `_Track` per instrument: the numeric cache object, retained row count, the
running digest and a `FeatureEngine`.

* Same object, longer prefix (the replay path built by `extend_causal_frame`): the digest is
  extended with the newcomer rows only (`_rows_bytes(source, n_old, n)`) — **no history is
  re-read** — and the engine rolls its Wilder/EMA/pivot state forward. Counter: `extensions`.
* New or shorter prefix: the retained rows can no longer be proved unchanged, so every key for that
  instrument is **dropped by name** (counter: `invalidations`), the digest is recomputed once, and
  the engine reseeds itself on the new identity (counter: `reseeds`).
* A frame without a retained numeric cache (`frame_at`) is still correct: its `df` is stable per
  frame object, so one bar's 28 readers hit, and the next bar invalidates by name.

### 2.3 Bounded memory

`OrderedDict` LRU with two hard bounds: `max_entries` (exact, default 512) and optional `max_bytes`
on an estimate of the retained value bytes. Evictions are counted; `stats()` publishes entries,
estimated bytes, computations, hits, misses, evictions, invalidations, extensions, reseeds and bars
observed.

### 2.4 Use from `observe_all_28` without changing semantics

`FeatureCache.observe_all_28(frame, opportunity, readings=…)` calls the registry's
`observe_all_28(frame, opportunity, readings=…, engine=track.engine)`. The dispatchers, the witness
metadata and the feature kernels are the registry's own; only the retained state is shared. The
`scoped(frame)` context manager exposes the same state to any other expert path.

Nothing was added to `domain/market.py`: the existing `_prefix_df` identity and
`extend_causal_frame` are the incremental primitive, and no public signature changed.

## 7. Residual risks and NOT_RUN

| Item | State | Reason |
|---|---|---|
| 40 legs / 12 months invalidation parity | **NOT_RUN** | no 40-leg/year tape in this worktree; single-leg Q1 measured |
| Cross-process / multi-threaded cache sharing | **NOT_RUN** | `FeatureCache` is single-threaded per feed by construction, like `FeatureEngine`; no concurrency contract claimed |
| Orders / fills / funding settlements | **NOT_RUN** | expert layer only; execution adapters are not in this slice |
| RSS under a 4 GiB cgroup | **NOT_MEASURED** | host run; see M0-08 §6 |
| `significant_swings` with strengths other than 10 on the real tape | **NOT_RUN** | the wired experts use strength 10; the spec machinery is tested synthetically |

Known behavioural detail, deliberately stated: values for a frame with **no** retained numeric cache
invalidate on every new frame (fail-closed: the prefix cannot be proved unchanged). That costs a
recompute, never a wrong value.

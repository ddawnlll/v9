## Objective

A single instrument's market state at one decision time, expressed as a versioned
schema derived **only** from point-in-time inputs (`ObservationView` +
`HorizonContext`). Scores are not probabilities, absent data is an explicit
`MISSING`/`UNKNOWN` dimension rather than a fabricated number, the record carries
no order authority, and every belief binds to the PIT inputs it used plus a
content hash.

## Implemented (`src/v8_next/belief/state.py`)

- `MarketBeliefV1` (frozen, `extra="forbid"`) with
  `instrument_id, decision_time_ns, max_input_available_at,
  input_observation_ids, dependency_fingerprint, policy_version, status,
  origin, quality, regime_label, regime, regime_candidate, candidate_streak,
  structure, volatility, liquidity, horizons, uncertainty, transition,
  changed_fields, missing_inputs, provenance, version_hash, advisory_only,
  order_authority`.
- `version_hash` = `canonical_digest("market_belief", <content> + schema_version)`
  (`v8_next.telemetry.identity`). Recomputed in the model validator: an absent
  hash is filled in, a mismatching hash is refused; `verify_version_hash()` is the
  explicit check used before reusing a previous belief. No wall clock participates,
  so replaying identical inputs reproduces the identical hash.
- `RegimeScores` carries `label: EpistemicLabel` = `SCORE`; `PROBABILITY` is
  rejected by this schema version (no calibration evidence exists). `definition`
  documents the scoring rule on every belief.
- Dimension models, each with an explicit absence path:
  - `StructureView` (`direction/swing_state/breakout_state` + window bounds;
    `MISSING` forbids carrying prices or a named direction);
  - `VolatilityView` (`level/range_bps/range_percentile/change_state`; `UNKNOWN`
    forbids carrying measured values);
  - `LiquidityView` (`availability: PRESENT|PARTIAL|MISSING|UNKNOWN`, mark,
    spread, open interest, funding, `missing_dimensions`, `proxy_only=True`
    pinned — an L2/fill claim is refused);
  - `HorizonsView` (one `HorizonAlignment` per timeframe in order, consistency,
    complete count, max as-of).
- `BeliefStatus` = `FRESH | STALE | ABSTAIN | UNKNOWN`; `ABSTAIN` must name
  `missing_inputs` and cannot name a regime; `FRESH` cannot carry
  `MISSING`/`UNKNOWN`/`CONTRADICTORY`/`AMENDED_FUTURE` quality; only `FRESH` may
  carry a transition event.
- `UncertaintyState` is a **state enum** (documented in the enum docstring as
  derived from evidence quality, top-two score margin, horizon consistency and
  liquidity availability — explicitly not a variance or confidence interval).
- `TransitionEvidence` with a deterministic `event_id` that re-derives from
  `(previous_state_id, from, to, reason, band, candidate/incumbent score, trigger
  ids, occurred_at_ns)`; tampering fails closed.
- `advisory_only` pinned `True`, `order_authority` pinned `False`; constructing
  otherwise raises.

## PIT binding

`advance` selects only observations with `available_at <= decision_time_ns`
(even when the supplying view's cut is later) and only bars with
`end_ns <= decision_time_ns`; `max_input_available_at` is the maximum availability
clock among exactly those inputs and is validated `<= decision_time_ns`.
`input_observation_ids` is the sorted, unique content-id set of the inputs used
(window bars + latest mark/quote/open-interest/funding observation).

## Acceptance evidence

- **Structured schema roundtrips** —
  `test_schema_roundtrips_and_replay_is_deterministic`: `model_dump_json` →
  `model_validate_json` yields an equal belief with the same `version_hash`.
- **Replay deterministic** — two `advance(None, …)` calls on the same view/context
  produce equal beliefs and identical `version_hash`; `belief_version_hash()`
  re-derives the stored hash.
- **Score ≠ calibrated probability** — `test_scores_are_scores_and_tampering_is_rejected`
  shows `RegimeScores(label=PROBABILITY)` is refused and a tampered belief is
  refused both by `verify_version_hash` and by revalidation.
- **Missing liquidity/mark is not fabricated** —
  `test_missing_liquidity_is_explicit_and_never_fabricated`: no channels →
  `availability=MISSING`, every numeric field `None`, `MARK`/`QUOTE` listed in
  `missing_dimensions`, quality `MISSING`; a malformed mark payload →
  `availability=UNKNOWN`, `mark_price=None` (still no number).
  `test_present_liquidity_reads_only_published_channels` shows the one path where
  numbers exist: values read from published MARK/QUOTE/OI/FUNDING payloads
  (spread computed from bid/ask and quantised).
- **Each belief binds to available PIT inputs + version hash** —
  `test_belief_binds_to_available_pit_inputs` resolves every id through
  `view.require_observation`, asserts `available_at <= decision_time_ns` and
  `max_input_available_at == max(available_at of the used inputs)`.
- **Future data cannot change a belief** — `test_future_data_cannot_change_a_belief`:
  mutating the caller's observation payloads after the view exists leaves the
  belief hash unchanged, and a view captured later (containing observations only
  available after the decision) reproduces the identical belief and input id set.
- **UNKNOWN/ABSTAIN first-class** — `test_absent_required_inputs_produce_an_abstain_belief`
  (no bars/horizon → `ABSTAIN`, `missing_inputs`, unknown dimensions, empty input
  ids) and `test_unknown_quality_blocks_a_fresh_state` (`quality=UNKNOWN` input →
  `status=UNKNOWN`, `is_actionable_evidence() is False`).
- **No order authority** — `test_schema_roundtrips_and_replay_is_deterministic`
  asserts the pinned flags and that `advisory_only=False`/`order_authority=True`
  are rejected.
- **No unavailable ex-ante dimensions** — `test_belief_carries_no_unavailable_ex_ante_dimensions`
  checks the names in `v8_next.telemetry.belief.UNAVAILABLE_EX_ANTE_DIMENSIONS`
  are neither schema fields nor accepted input (consistent with that module's
  invariant 1).

## Residual risks

- Regime/structure/volatility arithmetic is a documented heuristic over the last
  `window_bars` closes; it is deliberately not calibrated and makes no edge claim.
  Section 4.6 (B/C) falsification of the representation remains unproven.
- Only M15 bars are consumed for features; 1h/4h are represented through
  `HorizonsView` alignment state, not through their own bar arithmetic. A later
  issue may extend feature extraction per timeframe.
- `LIQUIDATION` observations are not consumed by v1, so they are intentionally
  excluded from the dependency fingerprint (recorded as a residual risk if a later
  version starts consuming them).
- Liquidity is proxy-only by construction (`proxy_only` pinned `True`); no L2
  book, sponsorship or fill model exists and none is claimed.

# F-03 — Durable research memory, audit receipts and agent-efficiency benchmark (#37)

Status: **IMPLEMENTED_WITH_EVIDENCE** (integration and final issue closure remain the director's call).

## Objective

The factory's default outcome is *not* a shipped change: most issues end `NO_EDGE`, blocked or
invalid. Those outcomes must be first-class, durable rows so the next shift does not pay for the
same dead end, and the fleet's output must be reported per compute-hour — issue completion,
verified findings, PR acceptance, token cost, CPU time, retries, memory high-water — with
anything unmeasured labelled `NOT_MEASURED` rather than defaulted. Negative receipts must
survive a restart, and uncontrolled OOS access must never occur on the path that records them.

## Design

**Append-only, content-addressed rows.** `ResearchMemory` is one SQLite file in WAL mode with
`synchronous=FULL` and `BEGIN IMMEDIATE` for writers — the same discipline as the F-01 queue
(one storage rule for the factory is easier to audit than two). No `UPDATE` and no `DELETE` is
issued by the module: a correction is a new row. `MemoryEvent` is a frozen pydantic model, so a
caller cannot mutate a returned row and believe the store changed.

**Replay-idempotent, not time-addressed.** `event_id = canonical_digest("factory-research-memory",
<content>)`, where content is every supplied field *except* `recorded_ns`; the insert is
`ON CONFLICT(event_id) DO NOTHING` and the stored row is returned. A coordinator that dies after
the commit and replays the same `record(...)` finds one row. Two genuinely distinct attempts
differ in `attempt` and are stored separately.

**Negatives are typed.** `FindingOutcome` = `VERIFIED | NO_EDGE | BLOCKED | INVALID | EXHAUSTED`.
`MemoryEvent.is_negative` covers the four non-verified outcomes, and `efficiency()` counts them
separately (`blocked`, `no_edge`, `invalid`, `exhausted`) so a blocked run is never read as
evidence of no edge.

**Unmeasured is not zero.** Costs are `Measurement(value, state)`; a metric is `MEASURED` only
when *every* row supplied it, otherwise `NOT_MEASURED` with `value=None`. A partial sum is never
presented as a total.

**Benchmark: caller-supplied, gated, then decisive.** `run_benchmark(baseline, treatment,
budget=...)` requires both arms on the same task ids (duplicates, mismatched lists, empty arms
raise `BenchmarkError`) and computes accepted-tasks/hour, tokens, tokens/accepted-task, retries,
wall/CPU hours and RSS high-water. `correctness_gate` and `budget_gate` are tri-state
(`PASS|FAIL|NOT_MEASURED`). A verdict is only produced when the comparison is sound: a known-bad
arm (failed gate) can never win, and an arm nobody could grade yields `NOT_COMPARABLE` — not a
loss. `zero wall time` cannot divide by zero, and `iter_report_rows` renders unmeasured fields
with their marker.

  It stores provenance (`code_sha`, `config_sha`, `dataset_role`, `oos_access`, …) rather than
  reaching for data itself: the memory never opens a dataset, so it cannot grant OOS access.

## Residual risks

- **All-or-nothing cost completeness.** Token/wall/CPU/RSS totals are `NOT_MEASURED` if *any*
  row lacks the field. That is honest but pessimistic: one `ATTEMPT` row recorded without costs
  makes the fleet total unknown. Documented policy; `events`/`issues` counts stay exact.
- **`accepted_prs` is not all-or-nothing.** PR acceptance is only defined for rows that report
  it (`reported_prs` says how many), because attempt/finding rows have no PR to accept. The
  distinction is deliberate and surfaced as two fields.
- **Content-addressed dedupe.** Two genuinely identical findings for the same issue+attempt with
  the same evidence/provenance collapse into one row. This is the crash-replay property; a
  caller that must record duplicates needs a distinguishing detail or a different attempt.
- **`efficiency()` is a full pass.** Three SQL aggregate queries plus two `GROUP BY`s; fine at
  research-memory scale, untested at millions of rows. No index exists on `recorded_ns` (no
  time-filtered query is offered yet).
- **Attempt/retry definition.** `attempts` counts distinct `attempt` numbers per issue; `retries`
  is that minus one per issue. A worker that never records an `ATTEMPT` row but only an
  `OUTCOME(attempt=1)` still counts one attempt (the distinct-attempt query spans all kinds).
- **The benchmark does not run anything.** Every number is caller-supplied; `run_benchmark`
  cannot detect a treatment that measured itself optimistically, and a "TIE" is exact float
  equality on accepted-per-hour.
- **No coupling to the queue or the ledger.** F-03 records what the worker reports; it does not
  reconcile queue history against memory rows (that is an audit concern). `Wall`/CPU hours are
  derived from caller measurements, not from `resource.getrusage`.
- **Concurrency.** Writers serialise on SQLite's lock; one connection per process is the
  documented contract (as with F-01). WAL requires a local POSIX filesystem; NFS is untested.

# M2-03 — Legal action priority and conflict-resolution policy

Objective: formalise which advisory actions are legal for each world state (issue #18) and make
conflict resolution deterministic, so later waves cannot override risk/venue uncertainty by
consensus.

## What was implemented

`src/v8_next/economics/legality.py` (new module, exports match WAVE_PLAN § Shared contracts):

- `PositionPresence` (NONE/OPEN/PENDING_INTENT/UNCERTAIN).
- `LEGAL_ACTION_TABLE` — module-level `MappingProxyType` with one frozen row per
  `(PositionPresence, VenueOrderStatus)` pair (28 rows), plus two frozen gate sets,
  `STALE_FORBIDDEN` and `UNARMED_FORBIDDEN`, both `{ENTER}`. Import guards assert the table is total
  over `position × venue` and that `PRECEDENCE` covers `DecisionAction` exactly.
- `LegalActionTable.legal(position, *, venue, stale, armed_opportunity) -> frozenset[DecisionAction]`
  — a table lookup minus the gate sets. No branch widens the set. Foreign values are rejected
  (`TypeError`) rather than coerced, so an unlisted venue string cannot slip past the closed enum.
- `resolve_conflict(candidates) -> DecisionAction` — deterministic risk-first precedence
  `EXIT > REDUCE > ABSTAIN > WAIT > HOLD > ENTER`; duplicates collapse, candidate order is
  irrelevant, an empty sequence raises.
- `resolve_legal_conflict(candidates, *, legal)` — intersects candidates with the legal set before
  applying precedence and returns `ABSTAIN` when nothing legal remains, so consensus cannot
  override legality.

Row semantics (all rows are data in `LEGAL_ACTION_TABLE`):

| position | venue | legal (fresh, armed) | rationale |
|---|---|---|---|
| NONE | SUBMITTED/ACCEPTED/PARTIALLY_FILLED/FILLED | WAIT, ABSTAIN | flat belief contradicts a live venue order ⇒ unreadable |
| NONE | CANCELED/REJECTED | WAIT, ABSTAIN, ENTER | terminal order, flat, entry may resume if armed |
| NONE | UNKNOWN | WAIT, ABSTAIN | fail-closed |
| OPEN | any known venue | WAIT, ABSTAIN, HOLD, REDUCE, EXIT | manage exposure; entry illegal (scale-in not enabled) |
| OPEN | UNKNOWN | WAIT, ABSTAIN | fail-closed; no blind exit |
| PENDING_INTENT | SUBMITTED/ACCEPTED | WAIT, ABSTAIN | in-flight entry: no second order, no blind exit |
| PENDING_INTENT | PARTIALLY_FILLED/FILLED | WAIT, ABSTAIN, HOLD, REDUCE, EXIT | partial fill is real exposure |
| PENDING_INTENT | CANCELED/REJECTED | WAIT, ABSTAIN, ENTER | intent resolved flat |
| PENDING_INTENT | UNKNOWN | WAIT, ABSTAIN | fail-closed |
| UNCERTAIN | any venue | WAIT, ABSTAIN | unreadable exposure is never acted on |

Gates applied after lookup: `stale=True` removes `ENTER`; `armed_opportunity=False` removes
`ENTER`. Consequences pinned by tests: venue `UNKNOWN` ⇒ only WAIT/ABSTAIN; stale ⇒ never ENTER;
no position ⇒ HOLD/REDUCE/EXIT never legal; open position ⇒ ENTER never legal; uncertain position
⇒ only WAIT/ABSTAIN.

Scale-in is deliberately absent from the table: there is no row and no flag that enables `ENTER`
with `OPEN`. Adding one requires a new documented policy, not an argument.

## Tests

`tests/test_legal_actions.py` — 591 tests (parameterised over all 112 world states), all passing:
table totality and immutability; `PRECEDENCE` coverage and exact order; the five fail-closed
invariants over every world state; explicit fixtures for unknown venue, stale inputs, open
position, flat position, pending intent (submitted / partial fill / terminal) and unarmed
opportunity; contradictory flat-belief rows; rejection of foreign position/venue/gate values;
duplicate-candidate collapse; empty-candidate rejection; conflicting expert evidence resolved
risk-first; order-invariance across permutations; consensus unable to override venue uncertainty
or staleness; legality-filtered resolution; and an exhaustive check that resolution never returns
an action outside the legal set.

## Residual risks / limits

- `resolve_conflict` alone knows nothing about legality by design; callers that combine expert
  candidates with a world state MUST use `resolve_legal_conflict` (or intersect with
  `LegalActionTable.legal` themselves) or risk resolving to an illegal action. This is documented
  in the module docstring and exercised by `test_resolution_never_returns_an_illegal_action`.
- `PENDING_INTENT` + `PARTIALLY_FILLED` is treated as exposure and therefore blocks `ENTER`; a
  future policy that wants to top up a partial fill needs an explicit new row, not a flag.
- `VenueOrderStatus` is observed state only; this module never derives it from order requests and
  never writes to a venue. No live-order path exists here (nothing in the module constructs,
  submits, amends or cancels an order).
- No economic or live-trading claims. BLOCKED items: none.

# M2-01 — Recurrent opportunity evaluations on the canonical book

Objective (issue #16): carry sovereign opportunity identity across time so that
watching / armed / admitted / invalidated / expired are separated from orders and
from strategy callbacks, with an append-only point-in-time status history that
replays identically. Acceptance: duplicate witnesses cannot create duplicate
opportunities; invalidation/expiry are deterministic and PIT; archived episodes
trace to decision receipts.

## What was implemented

### `src/v8_next/opportunities/book.py` (extended, existing semantics preserved)

Existing lifecycle mutators are untouched in behaviour: `insert`, `get`,
`update_status`, `on_candle`, `active_opportunities`, `all`, `__len__`,
`is_empty`. Every pre-existing test passes unchanged.

New append-only surfaces:

- `canonical_witness_ids(...)` — deduplicates and sorts witness ids; a blank id
  raises `StatusEventError`.
- `StatusEvent` (frozen pydantic model) — `event_id`, `opportunity_id`, `status`,
  `event_time_ns`, `available_at_ns`, `witness_ids`, `reason`, `sequence`.
  `available_at_ns < event_time_ns` is rejected. `event_id` is
  `canonical_digest("opportunity-status-event-v1", [...])`, so it is a versioned
  reference for the event.
- `insert(opportunity, *, witness_ids=())` — idempotent on the episode id and on
  witness ids. A witness already bound to an episode returns that canonical
  episode instead of minting a second opportunity; witnesses within one insertion
  are deduplicated. Market-created episode ids (`OpportunityRecord.create`
  digests) are never modified or re-minted.
- `update_status(...)` / `record_status(...)` — accept explicit
  `event_time_ns`/`available_at_ns`/`witness_ids`/`reason`; append exactly one
  `StatusEvent` before mutating live state, so an invalid PIT record cannot
  half-apply. Events must be non-decreasing in event time per episode; a
  backwards fact raises `StatusEventError` and leaves state untouched.
- `on_candle(...)` — appends `PRICE_INVALIDATION` / `TIME_EXPIRY` events stamped
  `candle.end_ns` (availability equal to the close), before the status change.
- `snapshot(as_of_ns) -> OpportunitySnapshot` — per episode, keeps only events
  with `event_time_ns <= as_of_ns` and `available_at_ns <= as_of_ns`, selects the
  newest by `(event_time_ns, sequence)`, and exposes a `EpisodeSnapshot` with the
  as-of `OpportunityRecord`, the status at that cut, the ordered `event_ids`
  (versioned references), the witness union and the decision ids knowable at the
  cut. `snapshot_id` is a canonical digest of the whole view.
- `link_decision(opportunity_id, decision_id, *, event_time_ns, available_at_ns)`
  — idempotent per `(opportunity, decision)` receipt; unknown episode returns
  `False`; blank ids and non-PIT availability raise.
- `archive(as_of_ns=None)` — terminal episodes (`INVALIDATED`/`EXPIRED`) at the
  cut, each with `terminal_event_id`, the full `event_ids`, and `decision_ids`, so
  an archived episode traces to decision receipts. Default cut is the book clock.

### `src/v8_next/opportunities/recurrent.py` (new)

- `RecurrentEvent` / `RecurrentOpportunityState` (frozen pydantic models):
  `opportunity_id`, lifecycle from `v8_next.domain.decision.OpportunityLifecycle`,
  append-only `history`, `last_evaluation_ns`, `witness_digest`. The state model
  re-validates history ordering, that `last_evaluation_ns` and `lifecycle` match
  the newest event, and that `witness_digest` equals the canonical digest of the
  union of recorded witnesses (tampered state fails pydantic validation).
- `bootstrap(record, *, witness_ids=())` — starts from the market-created record,
  stamped at the record's own `as_of_time_ns`.
- `advance(...)` — pure function. Idempotent per `(episode, evaluation_time)`:
  the identical payload returns the same state object and appends nothing; a
  different payload at a recorded instant raises `RecurrentConflictError`.
  Refuses non-PIT inputs (`available_at_ns > evaluation_time_ns`, negative
  clocks, a receding evaluation clock) with `NonPitEvaluationError`. Lifecycle is
  monotone `WATCHING -> ARMED -> ADMITTED`; `INVALIDATED`/`EXPIRED` are absorbing
  (terminal import from `domain.decision.TERMINAL_LIFECYCLES`), so invalidation
  and expiry replay identically and an episode is never resurrected.
- `witness_digest(...)` — order-independent digest of the witness set.

No D4-specific waiting rules exist in either module: only lifecycle legality and
PIT clock refusals.

## Tests

`tests/test_opportunity_recurrent.py` — 14 tests, all passing:

- duplicate/blank witnesses, duplicate witness on differently-shaped record
  (canonical episode wins), witness canonical ordering;
- as-of snapshot never exposes a later status change (fact 2h / published 3h),
  live book already updated while snapshots lag;
- append-only monotonic history, backwards event refused without half-apply,
  same-status no-op;
- snapshot determinism across two identical books and versioned event references
  (64-hex ids matching `status_history`);
- invalidation and expiry deterministic across replays, including the cut before
  the closing candle; `archive()` equality across replays;
- archive traces to decision receipts (link visible only once available,
  idempotent relink, terminal event id);
- recurrent idempotence, conflict on same-time different payload, non-PIT
  refusals, monotone/terminal-absorbing lifecycle, witness digest order
  insensitivity, tampered-state validation errors;
- recurrent state replayed against book snapshots reaches the same terminal
  lifecycle.

## Residual risks / limits

- `update_status` without an explicit clock uses the book clock (last candle or
  insert). That default is deterministic but coarse: PIT replays that need a
  finer clock MUST pass `event_time_ns`/`available_at_ns` explicitly via
  `record_status`.
- Status event times must be non-decreasing per episode. Late-arriving evidence
  can change availability, not facts; a caller that needs to restate an earlier
  fact must model it as a new episode, not rewrite history.
- Witness identity is bound 1:1 to an episode: a witness id reused across
  genuinely different opportunities will return the first episode. Callers that
  emit one evidence id for several opportunities must namespace it per episode.
- `snapshot()` exposes episodes whose creation event is knowable; it does not
  apply `active_opportunities`' validity window.
- The live `OpportunityRecord.status` still reflects the newest recorded event,
  even if that event is only available later; PIT consumers MUST read
  `snapshot(as_of_ns)` instead of `get()`.
- No execution, order or venue logic is touched. BLOCKED items: none.

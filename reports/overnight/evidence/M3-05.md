# M3-05 — Constraint-aware shadow portfolio challenger

Issue: #26 (M3-05). Branch `wave3/w3d`. Implementation commit
`70ffb9e340e6c3b0ddb3845dc0dca8e456d60e48`.

## Objective

Select among simultaneous opportunities under real equity, existing commitments,
correlation/sector exposure and hard risk constraints, reusing the inherited
allocator and account readings instead of introducing a second portfolio ledger.
Compare the challenger against the V8 allocator over identical opportunities.
Acceptance: cap, size precision, open/reserved exposure and risk priority are
respected on multi-asset fixtures; no shadow proposal is submitted natively and
no economic superiority is asserted.

## Implementation

### `src/v8_next/economics/portfolio_challenger.py` (new)

- `AllocationCandidate` (frozen dataclass): opportunity id, instrument,
  direction, requested notional, `risk_priority`, sector, correlation group,
  reference price, confidence, venue step/min/max/tick/min-notional. Decimal
  money is enforced at construction (a `float` is a `TypeError`), and structural
  identities (direction, bounds) are validated. No order authority is carried.
- `ChallengeOutcome` (closed set): `ADMITTED | BLOCKED_CAP | BLOCKED_EXPOSURE |
  BLOCKED_RISK | BLOCKED_PRECISION | BLOCKED_DUPLICATE_EXPOSURE`.
- `ChallengeReason` (stable discriminators) with a single reason→outcome map;
  `AllocationOutcome.__post_init__` rejects a reason/outcome mismatch and any
  denial that carries size or a binding cap.
- `allocate_challenger(candidates, *, equity, committed, max_gross_exposure,
  max_per_sector, risk_budget, step_sizes, instrument_committed=None,
  sector_committed=None) -> ChallengeResult`:
  - deterministic ranking `(-risk_priority, -confidence, opportunity_id,
    instrument, direction, requested_notional)` — input order is irrelevant;
  - capacity `min(equity, max_gross_exposure) - total_committed`;
  - `max_per_sector` applies to both the sector bucket and the correlation-group
    bucket; `risk_budget` is an independent notional ceiling charged
    conservatively with existing commitment;
  - quantities are converted from notional at `reference_price` and floored to
    the authoritative `step_sizes[instrument]`, then bounded by `max_size`;
  - declared candidate step must equal the authoritative map entry, the price
    must sit on the tick, and any legal quantity below `min_size` /
    `min_notional` is `BLOCKED_PRECISION` (no rounding up);
  - unknown (`None`/non-finite/negative) equity, committed capital, caps, risk
    budget or step map fails the whole run closed: every candidate is
    `BLOCKED_RISK/UNKNOWN_CONSTRAINTS`, `admitted_notional == 0`,
    `remaining_capacity == 0`, and the absent input names are reported;
  - positive `committed` requires per-instrument and per-sector attribution maps
    that each sum exactly to `committed`; absent attribution is
    `BLOCKED_EXPOSURE/UNKNOWN_EXPOSURE_DETAIL`, inconsistent attribution is
    `BLOCKED_RISK/INCONSISTENT_EXPOSURE_INPUT`;
  - a second candidate on an instrument already admitted in the batch, or a
    repeated opportunity id, is `BLOCKED_DUPLICATE_EXPOSURE`; pre-existing
    exposure on the instrument blocks a new entry (no netting model);
  - `ChallengeResult` (frozen) validates `total_committed == opening_committed +
    admitted`, rejects a fail-closed run that admits, and carries a
    `canonical_digest` over ranked outcomes and totals. Counterfactual notes
    (`COUNTERFACTUAL_NOT_COMMITTED`) are a separate container and are never
    added to committed or admitted notional.
- `BaselineAllocation` holds the inherited `allocate_ordered` inputs explicitly;
  `compare_to_baseline(candidates, baseline, ...) -> ChallengerComparison` runs
  both allocators, requires identical opportunity sets/instruments and a shared
  equity, and reports per-candidate baseline/challenger quantity, notional and
  delta plus totals. The comparison carries an explicit
  "no economic superiority" note and no preference field.
- Shadow-only surface: module imports only `v8_next.economics` / `v8_next.risk` /
  `v8_next.telemetry`; it never imports an adapter, `nautilus_trader` or an
  execution module, and constructs no order, campaign or adapter object.

## Residual risks

- Pre-existing commitment is attributed per instrument and per sector from the
  caller's maps. Correlation-group capacity is enforced within the batch only;
  a pre-existing cluster position that does not align with a supplied sector is
  not re-attributed. This is documented in the module and cannot free gross
  capacity (existing commitment is still fully charged).
- A positive `committed` without exact per-instrument/per-sector attribution is
  refused rather than guessed, so a caller that only knows the scalar must
  supply the split; otherwise the run is blocked.
- Price precision is validated against the tick but prices are never rounded:
  an off-tick reference price fails closed.
- Quantity is derived from a single reference price and floored to the lot step;
  no slippage, fee, funding or stop-band reservation is modelled (the baseline
  comparison exposes exactly that accounting difference).
- Duplicate opportunity ids are denied after the first ranked occurrence; the
  counterfactual note for the duplicate reuses its id (the result's
  cross-container invariant is only enforced when outcome ids are unique).

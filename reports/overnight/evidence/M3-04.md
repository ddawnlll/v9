# M3-04 — Factual occupancy attribution and blocked portfolio opportunities

Objective (issue #25): track choices denied by actual capacity, an open position
or risk reservations — without mislabelling counterfactuals as realized money.
Keep the factual decision log, the matched alternatives and simulated
counterfactual performance in separate containers, with PIT capacity states.
Acceptance: deterministic multi-opportunity fixtures show occupied/blocked
reasons and no double spending; realized PnL is strictly separate from
hypothetical PnL.

## What was implemented

### `src/v8_next/economics/occupancy.py` (new)

- `OccupancyOutcome` (closed set): `ADMITTED | OCCUPIED_CAPACITY | BLOCKED_RISK |
  BLOCKED_NO_CAPITAL | BLOCKED_POSITION | EXPIRED | INVALIDATED | UNKNOWN`.
  `is_admitted` / `is_blocked` properties; every non-admission is a denial.
- `OccupancyReason` (stable wire discriminators): `CAPACITY_AVAILABLE`,
  `CAPACITY_CONSUMED`, `DUPLICATE_OPPORTUNITY`, `RISK_RESERVED`, `NO_CAPITAL`,
  `POSITION_OPEN`, `POSITION_PENDING`, `CAPACITY_UNKNOWN`, `CAPACITY_FUTURE`,
  `CAPACITY_INCONSISTENT`, `OPPORTUNITY_EXPIRED`, `OPPORTUNITY_INVALIDATED`.
- `OccupancyRequest` (frozen): opportunity id, instrument, requested notional
  (positive, finite Decimal), `expires_at_ns`, `status`.
- `CapacityState` (frozen, PIT): `as_of_ns`, `available_at_ns`, `source`,
  `position` (imported `PositionPresence`), and optional `equity`,
  `committed_notional`, `reserved_notional`, `risk_budget_notional`,
  `position_notional`. Missing values stay `None`. `digest()` is a canonical
  digest of the whole reading; `missing_fields()` names absent required fields.
- `OccupancyEntry` (frozen): `entry_id`, opportunity/instrument, decision time,
  outcome, reason, `requested_notional`, `committed_before/after`,
  `exposure_before/after`, `available_capacity_after`, `equity`, capacity digest,
  and the separated `realized_pnl` / `hypothetical_pnl` (both default `None`).
  The model rejects a record carrying both, realized PnL on a non-admission, and
  hypothetical PnL on an admission.
- `CounterfactualPerformance` (frozen): explicitly simulated PnL for a denied
  alternative; refuses admitted outcomes and non-finite values.
- `OccupancyLedger`:
  - `evaluate(request, capacity, decision_time_ns)` — deterministic factual
    decision. Ordering: lifecycle terminal (`EXPIRED`/`INVALIDATED`) → capacity
    PIT (`CAPACITY_FUTURE` if `available_at_ns`/`as_of_ns` after the clock) →
    unreadable capacity (`CAPACITY_UNKNOWN` for absent fields or `UNCERTAIN`
    position) → internally inconsistent capacity (`committed > equity` →
    `CAPACITY_INCONSISTENT`) → `POSITION_OPEN` / `POSITION_PENDING` →
    duplicate already-admitted opportunity (`OCCUPIED_CAPACITY`) → risk budget
    (`BLOCKED_RISK`) → capacity (`OCCUPIED_CAPACITY` with `committed > 0`,
    otherwise `BLOCKED_NO_CAPITAL`) → `ADMITTED`.
  - Committed capital is the conservative union `max(ledger committed,
    observed committed)`; a stale lower reading cannot free capital.
  - `realize(opportunity_id, realized_pnl, decision_time_ns)` — only for
    admitted opportunities; denied → `NotAdmittedError`; a different second
    value → `DuplicateRealizationError`; identical replay is idempotent. The
    factual entry is replaced with one carrying `realized_pnl`.
  - `record_counterfactual(opportunity_id, hypothetical_pnl, ...)` — only for
    capacity-denied alternatives (admitted → `CounterfactualOnAdmittedError`,
    terminal lifecycle → `CounterfactualNotApplicableError`, unknown →
    `UnknownOpportunityError`, different second number →
    `DuplicateCounterfactualError`). Stored in its own map; never written onto a
    factual entry.
  - `decision_log()` (every factual entry), `matched_alternatives()` (capacity /
    position / risk / unknown denials only), `counterfactual_performance()`
    (simulated records only), `realized_pnl_total()` and
    `hypothetical_pnl_total()` as separate accessors.
  - `assert_no_double_spend()` — every admission commits exactly the requested
    notional, no admission exceeds the equity seen at that instant, denials never
    change committed capital, and the ledger's commitment equals the admitted
    maximum.

## Tests

`tests/test_occupancy_attribution.py` — 21 tests, all passing:

- capacity-limited admission: first 600/1000 admitted, second 600 blocked as
  `OCCUPIED_CAPACITY` / `CAPACITY_CONSUMED` with unchanged committed/exposure;
- multi-opportunity fixture (600 admitted, 600 blocked, 300 admitted, 200
  blocked): admitted sum 900 ≤ equity 1000, no entry above equity;
- duplicate evaluation at the same and at a later time cannot double-count
  capital (`DUPLICATE_OPPORTUNITY`, committed stays 600);
- open and pending positions block with `POSITION_OPEN` / `POSITION_PENDING`
  and reserve nothing; risk reservation blocks exactly the request that would
  breach the budget while a smaller request fits;
- zero equity → `BLOCKED_NO_CAPITAL`;
- parameterised fail-closed matrix (future `available_at`, future `as_of`,
  missing equity/committed/position notional, `UNCERTAIN` position, inconsistent
  committed > equity) → `UNKNOWN` with the right reason and zero commitment; an
  unknown-state denial does not reserve, so a later readable evaluation admits;
- expired/invalidated requests are never admitted and are excluded from
  alternatives, and cannot receive a counterfactual;
- realized vs hypothetical separation: blocked alternative hypothetical +90,
  admitted realized −10; totals are −10 and +90, factual entries never carry
  hypothetical PnL, simulated records never carry realized PnL, and the totals
  differ;
- denied opportunities can never be realized; admitted ones cannot receive a
  counterfactual; unknown opportunities raise;
- realization/counterfactual idempotence and non-revisability;
- deterministic replay of entry ids/outcomes/reasons and committed totals;
- schema guards: mixed PnL rejected, realized on blocked rejected, hypothetical
  on admitted rejected, non-positive/non-finite notional rejected.

## Residual risks / limits

- `risk_budget_notional` is expressed in the same notional unit as commitment
  (not a per-trade risk measure). This module attributes occupancy, not risk; a
  caller needing risk-unit attribution must convert before calling.
- Committed capital is not released: there is no close/release API in this
  ticket, so a long-lived ledger keeps conservatively charging admitted
  notional. A later ticket that needs capital recycling must add an explicit
  `release` record rather than mutating history.
- `committed_notional` from the capacity snapshot is unioned conservatively
  (`max`); an external release is not observed until a later capacity reading
  reports it. The ledger never frees capital from its own `realize`.
- Terminal lifecycle requests are classified before capacity PIT validation.
  That ordering is deliberate (an invalidated opportunity cannot spend anything),
  and it is pinned by tests.
- Counterfactual PnL is stored only for outcomes in the capacity-denial set;
  expiry/invalidation have no counterfactual in this module.
- No venue, order or execution path exists here. BLOCKED items: none.

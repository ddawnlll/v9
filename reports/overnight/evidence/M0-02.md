# M0-02 — Independent two-campaign accounting oracle

**Issue:** #3 · **Worker:** W3 (`AuditOracle`) · **Branch:** `wave1/w3`
**Base commit:** `0b69fc45c197354600256963249ca7b1f19b6bbd` (main, read-only reference)

## Objective

Recompute, fully independently, per-order fills, fees, funding, realized PnL, the final
mark and final equity for two concurrent campaigns; hard-fail on swapped campaign ids,
duplicated fills and duplicated fees; and keep provenance and arithmetic reconcilable.

## What was implemented

New module `src/v8_next/audit/oracle_two_campaign.py`:

- Frozen, `slots=True` dataclass input contract built from hand-writable source records:
  `CampaignRecord`, `OrderRecord`, `FillRecord` (carrying `fee_id` provenance),
  `FundingRecord`, `MarkRecord`. Money is `Decimal` only — floats are rejected at
  construction.
- `recompute(*, campaigns, orders, fills, funding=(), marks)` is a pure function over
  those records. It imports **no** engine aggregation path (asserted by an AST test):
  no `v8_next.adapters`, no `audit.pipeline`, no `audit.trade_metrics`.
- FIFO lot accounting with division-free, exact `Decimal` arithmetic; realized PnL is
  attributed to the closing order; the single final mark values open lots.
- `OracleReport` exposes `CampaignLedger` per campaign, `OrderLedger` per order
  (filled quantity, notional, fees, realized PnL, fill ids), total initial/final equity,
  and a canonical `provenance_digest` that is invariant to input ordering.
- Typed failures via `OracleViolation` carrying an `OracleViolationCode` and the offending
  record id: `DUPLICATE_FILL`, `DUPLICATE_FEE`, `DUPLICATE_ORDER`, `DUPLICATE_FUNDING`,
  `DUPLICATE_MARK`, `ORPHAN_FILL/ORDER/FUNDING/MARK`, `CAMPAIGN_MISMATCH`,
  `INSTRUMENT_MISMATCH`, `SIDE_MISMATCH`, `OVERFILL`, `FEE_PROVENANCE_MISSING`,
  `EVENT_TIME_OUT_OF_RANGE`, `MARK_BEFORE_FILL`, `MISSING_MARK`,
  `ARITHMETIC_MISMATCH`.
- `reconcile_aggregate(report, aggregate)` compares the independent ledger to an engine
  aggregate **supplied as data** (campaign set and every final equity must match exactly).

Covered negative cases: swapped campaign id on a fill (`CAMPAIGN_MISMATCH`), a
cross-campaign relabel of both order and fills (`INSTRUMENT_MISMATCH`), duplicated fill
(`DUPLICATE_FILL`), duplicated fee id (`DUPLICATE_FEE`), orphan fill (`ORPHAN_FILL`),
missing mark (`MISSING_MARK`), mark before the last fill (`MARK_BEFORE_FILL`), aggregate
mismatch and campaign-set mismatch (`ARITHMETIC_MISMATCH`), float money rejected.

## Residual risks / limits

- The oracle does not model margin, liquidation, or funding accrual between settlement
  rows; funding is the exact sum of supplied `FundingRecord.amount` values.
- FIFO is a declared convention, not a venue-reconciled one. An engine using average cost
  will differ on multi-lot partial closes.
- `reconcile_aggregate` compares only final equity per campaign; it does not reconcile
  intermediate fills against venue statements.
- No economic or live-trading claim is made or implied.
